Variant 1
PWA Standalone
Runs with zero browser chrome — no address bar, no keyboard URL indicator injection point. Complete bypass if Chrome only injects the real URL into browser UI chrome.
Requires: Add to Home Screen → open from home screen

Variant 2
VirtualKeyboard overlaysContent
Sets navigator.virtualKeyboard.overlaysContent = true so the keyboard overlays content instead of resizing the viewport. Chrome switches keyboard-handling path — URL injection may not run.
Chrome Android / desktop only — not supported on iOS Safari
Variant 3
inputmode="none" + virtualKeyboard.show()
Suppresses the browser's automatic keyboard via inputmode="none", then forces it up programmatically. URL injection is likely tied to the standard focus→keyboard flow, not the programmatic path.
Chrome Android / desktop only — not supported on iOS Safari
Variant 4
Date / Time wheel picker
type="time" shows an iOS wheel picker instead of a keyboard — no keyboard accessory bar exists so Chrome has nowhere to inject the real URL. Fake bar positions above the picker.
iOS Safari + Chrome iOS — wheel picker replaces keyboard entirely
